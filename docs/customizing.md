# Customizing the template

## Rename the project

The template uses the package scope `@app/*` and the workspace name `app-frontend`. To rebrand:

1. Search-and-replace `@app/` with your scope (e.g. `@myproject/`) across the repo (workspace package names, imports, scripts in `package.json`).
2. Update the root `name` in `package.json`, the values in `apps/admin/.env.example`, and the strings shown in `apps/admin/index.html` and `apps/admin/src/components/layout/Sidebar.tsx`.
3. Update the storage keys in `packages/api-client/src/auth-storage.ts` (`app.auth.access`, `app.auth.refresh`) and `apps/admin/src/stores/authStore.ts` (`AUTH_SESSION_STORAGE_KEY`) if you want the localStorage namespace to match your brand. Renaming will sign out any existing sessions on first deploy.
4. Run `pnpm install` to rewrite the lockfile and re-resolve workspace links.

## Switch the registration mode

`VITE_REGISTRATION_MODE` drives the UI. It must match the backend's `REGISTRATION_MODE` setting.

| Mode | What the UI shows |
|------|-------------------|
| `CLOSED` | Only the sign-in form. No public routes for sign-up or invitations. |
| `INVITATION` | Sign-in form + a hint about invitations. The `/invitations/:token` route is always available so users can accept an invitation from a manually-shared link. |
| `PUBLIC` | Sign-in form + sign-up link. `/register` becomes a fully usable page. |

Invitations also work in `CLOSED` and `PUBLIC` mode — they are simply not advertised on the login screen. Admin and superadmin users always see the **Invitations** entry in the sidebar.

## Remove the Notes feature

The Notes feature is included as a CRUD reference. To delete it:

1. Remove `apps/admin/src/features/notes/`, `apps/admin/src/routes/notes/`, and the two test files under `apps/admin/src/__tests__/NotesListPage.test.tsx` / `NoteFormPage.test.tsx`.
2. Drop the `/notes*` routes from `apps/admin/src/routes/index.tsx`.
3. Drop the **Notes** entry from `apps/admin/src/components/layout/Sidebar.tsx`.
4. Remove the Notes card from `apps/admin/src/routes/dashboard/DashboardPage.tsx`.
5. Regenerate the API client after the backend drops its `notes` app: `pnpm run generate:api`.

## Add a new feature

Follow the structure used by Notes:

1. **Hooks**: create `apps/admin/src/features/<feature>/hooks.ts` and wrap the generated endpoints with TanStack Query (`useMutation` / `useQuery`).
2. **Pages**: create `apps/admin/src/routes/<feature>/` with the list page, detail page, and form page as needed.
3. **Routes**: register them in `apps/admin/src/routes/index.tsx` (typically inside the `ProtectedRoute` + `AppLayout` block).
4. **Sidebar**: add a `NavItem` in `apps/admin/src/components/layout/Sidebar.tsx`. Set `adminOnly: true` if it should only be visible to `ADMIN`/`SUPERADMIN`.
5. **Tests**: cover the page with Testing Library + Vitest, mocking `useApiClient` like the existing tests do.

## Generated API client

`packages/api-client/src/generated/schema.ts` is autogenerated. **Never edit it by hand** — change the backend and regenerate. The barrel `packages/api-client/src/index.ts` re-exports the schemas you most often need (`User`, `LoginRequest`, `LoginResponse`, `AppPaths`, `components`).
