# app-frontend

Frontend monorepo template (WTemplate).

This repository is a reusable starting point for new SPA + Django REST API projects. It pairs with the `wtemplate-backend` template and provides:

- A typed API client autogenerated from the backend OpenAPI schema.
- JWT auth with persistent session and silent refresh.
- Admin panel scaffolding (login, protected routes, layout).
- A registration system with three modes (CLOSED, INVITATION, PUBLIC).
- An example CRUD feature (Notes) as a reference for building new features.

## Tech stack

- **React 18** + **Vite** + **TypeScript** (strict)
- **Tailwind CSS** + **shadcn/ui**
- **TanStack Query** for server state
- **React Hook Form** + **Zod** for forms and validation
- **Zustand** for client state (with `persist` for session)
- **openapi-fetch** + **openapi-typescript** for the API client
- **pnpm workspaces** monorepo
- **Vitest** + **Testing Library** for tests
- **GitHub Actions** CI

## Layout

```
app-frontend/
├── apps/
│   └── admin/      # SPA for administrators
└── packages/
    ├── shared/     # Shared hooks, utilities, validators
    └── api-client/ # Generated types and API client
```

## Prerequisites

- **Node.js** >= 20 (see `.nvmrc`)
- **pnpm** >= 9 — `npm install -g pnpm` or https://pnpm.io/installation
- A running backend (see `wtemplate-backend`).

## Quick start

```bash
pnpm install
pnpm run generate:api      # Regenerate the API client from the backend OpenAPI
pnpm run dev:admin         # Start the admin SPA on http://localhost:5173
```

The dev server proxies `/api` to `http://localhost:8000` by default (configurable in `apps/admin/vite.config.ts`).

## Environment variables

`apps/admin/.env.local` (not committed):

| Variable | Description | Example |
|----------|-------------|---------|
| `VITE_API_BASE_URL` | Backend base URL. Leave empty in dev to use the Vite proxy. | `` |
| `VITE_APP_NAME` | Display name for the app. | `App` |
| `VITE_REGISTRATION_MODE` | Registration mode: `CLOSED`, `INVITATION`, `PUBLIC`. Must match the backend. | `CLOSED` |

## Typed API client

The `@app/api-client` package contains types and a wrapper around `openapi-fetch` that are **generated automatically** from the backend OpenAPI schema. This keeps frontend and backend in sync.

### Regenerate

When the backend changes an endpoint:

1. Ensure the backend is running (defaults to `http://localhost:8000/api/schema/`).
2. From the repo root: `pnpm run generate:api`.
3. Commit with `chore(api-client): regenerate types from backend OpenAPI`.

### Target a different environment

```bash
OPENAPI_URL=https://staging.example.com/api/schema/ pnpm run generate:api
```

### Rules

- **Never edit generated files by hand** under `packages/api-client/src/generated/`. Change the backend and regenerate.
- Generated files **are committed** so the repo works without a running backend.
