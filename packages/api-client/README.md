# @app/api-client

Typed API client. **Types are generated automatically** from the backend OpenAPI schema (`drf-spectacular`).

## Philosophy

- `src/generated/schema.ts` is **autogenerated**. Never edit it by hand.
- The client wraps `openapi-fetch` with those types, so frontend and backend never drift.
- When the backend adds or changes an endpoint, regenerate and TypeScript points at every affected callsite.

## Regenerating the client

With the backend running (defaults to `http://localhost:8000/api/schema/`):

```bash
pnpm run generate:api
# or from the repo root:
# pnpm --filter @app/api-client generate
```

To target a different environment:

```bash
OPENAPI_URL=https://staging.example.com/api/schema/ pnpm run generate
```

## Public API

```ts
import { createApiClient, authStorage } from '@app/api-client';

const api = createApiClient({ baseUrl: 'http://localhost:8000' });

// Login
const { data, error } = await api.POST('/api/v1/auth/login', {
  body: { email: 'a@b.com', password: 'secret' },
});
if (data) {
  authStorage.setTokens(data.access, data.refresh);
}
```

The client:

- Attaches `Authorization: Bearer <access>` to authenticated requests.
- Detects `401`, calls `/api/v1/auth/refresh` with the refresh token, retries the original request.
- If the refresh fails, dispatches an `auth:logout` event (configurable) so the app can sign out.

## Errors

```ts
import { ApiError, AuthError, ValidationError } from '@app/api-client';
```

`ValidationError.fieldErrors` is a `{ field: [messages] }` map when the backend responds with 400 and field-level errors (DRF format).
